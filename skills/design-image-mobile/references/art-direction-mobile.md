# 모바일 아트디렉션 레퍼런스

## 0. 이 문서의 목적 / 사용법

이 문서는 `design-image-mobile` 스킬이 프롬프트를 구성할 때 읽는 아트디렉션 가드레일이다. 추상적인 디자인 이론이 아니라 **이미지 모델이 실제로 적용할 수 있는 구체적·렌더 가능한 형태 지시**만 담는다. 목표 품질 기준은 "그럴듯한 목업"이 아니라 **App Store 피처드 수준의 앱 화면 레퍼런스 이미지**다.

**대원칙: 모든 값(색·폰트·카피·브랜드명)은 DESIGN.md 토큰에서 가져온다.** 이 문서는 형태·구도·화면 구조·금지 패턴을 정의하며, 값을 창작하지 않는다. 둘이 충돌하면 DESIGN.md가 정답이다.

사용법: §1 핵심 디렉티브로 목적을 확인 → §2에서 플랫폼 모드 하나를 결정 → §3~§4 화면-우선·일관성 규칙 적용 → §5 플로우 논리 점검 → §6 디바이스 목업 프레임 규칙 확인 → §7~§9 세부 UI 규칙 → §10 레이아웃 → §11 이미지·텍스처 → §12 아이코노그래피 → §13 anti-mobile-AI-tells로 네거티브 점검 → §14 스타일 변주 엔진으로 방향 조합 → §15 텍스트·타이포·여백 → §16 카테고리별 바이어스 적용 → §17 포맷·품질 체크리스트로 최종 판정.

## 1. 핵심 디렉티브

이 스킬이 만드는 이미지는 **앱의 실제 화면과 플로우를 보여주는 레퍼런스 이미지**다. 감상용 아트워크가 아니다.

**generic 목업이 아니라 app-native 프리미엄 화면·플로우 이미지다.** 모든 화면은 그 앱의 것으로 읽혀야 한다 — 어떤 앱이든 꽂을 수 있는 빈 껍데기 목업이 아니라, DESIGN.md에서 가져온 실제 색·폰트·카피가 들어간 살아있는 화면.

- **이미지만**: 코드 모드 전환 금지. 이 스킬은 이미지 레퍼런스를 만드는 단계다.
- **화면 구조가 읽혀야 한다**: 탑바·내비게이션·콘텐츠 영역·바텀바의 계층이 명확해야 한다.
- **계층이 읽혀야 한다**: 제목 → 서브헤드 → 바디 → CTA의 시각적 크기 차이가 눈에 보여야 한다.
- **브랜드 요소가 실제처럼 느껴져야 한다**: DESIGN.md의 실제 색, 실제 폰트, 실제 제품명이 들어간다. 가짜 브랜드명·플레이스홀더 텍스트는 없다.
- **구현 근거가 있는 결정만**: 장식 때문에 넣은 요소가 아니라 기능·정보 계층에서 나온 결정이어야 한다.

## 2. 플랫폼 모드

**iOS-native / Android-native / 크로스플랫폼 중 하나를 게이트1에서 결정하고, 이후 모든 화면에 일관 적용한다. 섞지 않는다.**

### iOS-native 바이어스
- 청결하고 절제된 미감. 여백이 넉넉하다.
- 탑에 Large Title 또는 Inline Title, 하단에 탭바(Tab Bar, 홈 인디케이터 공간 포함).
- 세이프에어리어 상단·하단을 철저히 인지. 홈 인디케이터 공간을 침범하지 않는다.
- 차분하고 부드러운 전환 암시. 시트(Sheet)·풀다운 메뉴·스와이프 제스처 공간 고려.
- 전반적으로 빛이 충분하고 그림자가 얕다.

### Android-native 바이어스
- Material Design 컴포넌트 리듬. 일관된 간격 그리드.
- 탑에 App Bar(Top App Bar), 하단에 Bottom Navigation Bar 또는 Navigation Rail.
- FAB(Floating Action Button)이 적절한 화면에 자리잡음.
- 상태바 색이 앱 테마와 자연스럽게 이어짐.
- 엣지 투 엣지 레이아웃, gesture navigation bar 공간 인지.

### 크로스플랫폼 바이어스
- 특정 OS 고유 컴포넌트(iOS탭바 + Android FAB 혼재)를 피하고 보편 패턴 사용.
- 하단 탭 내비게이션은 두 플랫폼에서 모두 자연스러운 형태로.
- 상태바·홈 인디케이터 공간은 iOS 기준으로 여유있게 처리(더 보수적이라 양쪽 통과).
- React Native / Flutter 계열의 보편적 디자인 언어.

## 3. 화면-우선·충분한 화면 수·크롭 금지

**요청된 화면 수만큼 개별 이미지를 생성한다.** 큰 이미지 하나를 만들어 잘라서 여러 화면처럼 쓰지 않는다.

- **1화면 = 1이미지**: 여러 화면을 한 프레임에 합치지 않는다. 개발자가 분리해 구현할 수 없기 때문이다.
- **크롭 금지**: 이전에 생성한 큰 이미지에서 화면 하나를 잘라내지 않는다. 해상도와 가독성이 보장되지 않는다. 각 화면을 새로 생성한다.
- **충분한 화면 수**: 플로우를 이해하는 데 필요한 화면이 빠지면 안 된다. 게이트1에서 확정한 화면 목록을 빠짐없이 만든다.
- **가독성 우선**: 한 화면 안에 너무 많은 요소를 우겨넣어 텍스트가 작아지는 것보다, 화면 수를 충분히 늘려 각 화면을 명확하게 만드는 것이 낫다.

## 4. 앱 디자인 바이블(일관성)

멀티 화면 시리즈는 **같은 앱에서 캡처한 것처럼** 느껴져야 한다. 화면마다 스타일이 달라지면 한 앱처럼 읽히지 않는다.

**한 시리즈 전체에서 고정하는 요소:**
- **플랫폼·OS**: §2에서 결정한 플랫폼 모드를 모든 화면에 일관 적용.
- **디바이스 프레임**: 동일 디바이스 모델, 동일 스케일. 화면마다 디바이스가 달라지지 않는다.
- **팔레트**: DESIGN.md 토큰 팔레트를 모든 화면에 일관 적용. 화면마다 테마 색이 교체되지 않는다.
- **타입 스케일**: 제목·서브헤드·바디·라벨의 크기 비율이 모든 화면에서 동일. 폰트는 DESIGN.md 토큰에서.
- **간격·radius**: 컴포넌트 간 간격, 카드·버튼·이미지의 모서리 반경이 일관.
- **아이콘**: 같은 아이콘 스타일(stroke 굵기·fill 유무·크기). §12 아이코노그래피 참고.
- **이미지 트리트먼트**: 사진이 들어가는 경우 처리 방식(컬러·마스크·오버레이 강도)이 일관.

## 5. 논리적 플로우

**화면 순서가 믿을 만한 사용자 여정을 형성해야 한다.** 왜 이 화면 다음에 저 화면인지 이유가 있어야 한다.

- **게이트1 확정 플로우를 따른다**: 사용자와 합의한 플로우를 그대로 구현한다. 임의로 화면을 추가하거나 순서를 바꾸지 않는다.
- **맥락 연속성**: 화면2의 내용은 화면1에서 사용자가 한 행동의 결과여야 한다. 전혀 무관한 화면들을 묶지 않는다.
- **상태 일관**: 로그인 화면 이전에 홈 화면이 나오는 것처럼 상태가 앞뒤로 모순되지 않는다.
- **빠진 화면 경보**: 플로우 중간에 논리적으로 반드시 있어야 하는 화면이 빠져 있으면 사용자에게 알린다.

## 6. 디바이스 목업 프레임 규칙

모바일 화면은 **디바이스 프레임 안에 담아 렌더한다**. 규칙:

- **한 시리즈 동일 디바이스·동일 스케일**: 화면마다 다른 폰 모델, 다른 크기가 나오지 않는다.
- **캔버스 균등 여백**: 상하좌우 여백이 균등하다. 폰이 캔버스 한쪽 끝에 붙거나 잘려서는 안 된다.
- **폰이 캔버스 끝에 닿지 않음**: 여백이 없는 꽉 찬 목업은 숨막히게 느껴진다. 사방에 공간을 남긴다.
- **소프트 섀도**: 폰 프레임에는 얕고 절제된 소프트 드롭 섀도를 적용한다. 과장된 3D 그림자는 금지.
- **콘텐츠가 주인공**: 프레임이 콘텐츠보다 크게 느껴지면 안 된다. 디바이스 프레임은 콘텐츠를 돋보이게 하는 틀이지, 그 자체가 주인공이 아니다.

## 7. 온보딩·첫 화면 청결

온보딩과 첫 인상 화면은 특히 엄격하게 관리한다.

- **온보딩 슬라이드 반복 금지**: 동일한 레이아웃 템플릿을 배경색만 바꿔 반복하지 않는다. 각 슬라이드는 전달하는 메시지와 강조점이 달라야 한다.
- **첫 화면 한 초점**: 첫 화면에서 사용자의 시선이 어디로 가야 하는지 명확해야 한다. 동시에 강조되는 요소가 여럿이면 안 된다.
- **짧은 헤드라인**: 첫 화면 헤드라인은 간결하고 강하게. DESIGN.md §1 제품 설명에서 실제 가치를 끌어낸다.
- **명확한 1 CTA**: 첫 화면의 주요 행동 유도는 하나다. 여러 CTA를 동등하게 배치하지 않는다.

## 8. 세이프에어리어·시스템 영역

**포스터가 아니라 진짜 앱 화면이다.** 시스템 영역을 인지하고 존중한다.

- **상태바(Status Bar)**: 상단에 상태바 공간을 확보한다. 배경색과 자연스럽게 이어지게 처리한다.
- **탑바(Navigation Bar / App Bar)**: 화면 목적에 맞는 탑바가 자리잡아 있다. iOS의 경우 Large Title 또는 Inline Title 패턴.
- **바텀 내비게이션(Tab Bar / Bottom Navigation Bar)**: 해당 플랫폼의 하단 내비게이션이 적절한 화면에 표시된다.
- **홈 인디케이터·제스처 공간**: 하단 홈 인디케이터(iOS) 또는 제스처 내비게이션 공간(Android)을 침범하지 않는다. 콘텐츠나 버튼이 이 영역에 걸리지 않아야 한다.
- **키보드 오버랩**: 입력 필드가 있는 화면에서는 소프트 키보드가 올라온 상태를 고려해 핵심 요소가 가려지지 않는 레이아웃을 사용한다.

---

## 9. 내비게이션

**사용자가 이미 익숙한 패턴을 사용한다.** 낯선 내비게이션 구조는 학습 비용을 높인다.

- **친숙 패턴**: 탭바(Tab Bar)·스택 내비게이션(Stack Navigation)·바텀 시트(Bottom Sheet)·세그먼트 컨트롤(Segment Control)·드로어(Drawer) 등 해당 플랫폼에서 검증된 패턴.
- **과적재 금지**: 탭바에 탭이 5개 이상이면 과적재다. 탭 하나의 역할이 명확해야 한다.
- **깊이 절제**: 스택 탐색이 3단계를 넘으면 사용자는 길을 잃는다. 가능하면 평탄한 정보 구조를 지향한다.
- **뒤로가기 명확**: 뒤로 갈 수 있는 화면에는 뒤로가기 버튼이 명확히 보인다.

---

## 10. 클린 레이아웃

**단순하고 명확한 컨테이너가 복잡한 중첩보다 낫다.**

- **box-in-box 금지**: 카드 안에 또 카드, 그 안에 또 다른 컨테이너가 중첩되는 구조.
- **중첩 카드 스택 금지**: 카드들이 겹쳐 쌓여 있는 것처럼 보이는 과도한 depth 표현.
- **과밀 위젯 금지**: 한 화면에 차트·메트릭·목록·CTA·배너가 동시에 들어가는 대시보드 과밀 패턴.
- **더 적고 명확한 컨테이너**: 섹션당 하나의 핵심 메시지. 정보를 덜어내는 용기가 필요하다.
- **여백이 디자인이다**: 빈 공간을 채우려는 강박을 버린다. 충분한 여백이 콘텐츠를 숨쉬게 한다.

---

## 11. 이미지·텍스처·이미지-뒤-텍스트

- **카테고리에 맞는 이미지**: 앱 카테고리와 어울리는 이미지만 사용한다. 재고 사진 느낌의 비즈니스 핸드셰이크·웃는 팀원 사진은 금지.
- **텍스트 뒤 이미지엔 가독성 보호**: 이미지 위에 텍스트가 올라가는 경우, 페이드·마스크·스크림(반투명 오버레이)으로 텍스트 가독성을 반드시 확보한다. 텍스트가 이미지와 충돌해 읽히지 않으면 실패다.
- **과한 그레인 금지**: 텍스처나 노이즈 효과는 아주 미세하게만 허용한다. 필름 그레인처럼 두드러지는 텍스처는 앱 이미지에 어울리지 않는다.

## 12. 아이코노그래피

**아이콘은 앱의 디자인 언어 일부다.** 아무 아이콘이나 가져다 쓰지 않는다.

- **generic 개발자 툴 아이콘 회피**: Lucide·Feather·Material Icons 등 개발 도구에서 바로 꺼낸 raw 아이콘 느낌. 실제 앱처럼 손이 닿은 느낌이 없다.
- **확정 자산 우선**: `.design/assets/icon/*.svg`에 확정된 아이콘 패밀리가 있으면 그 패밀리의 스타일을 우선 반영한다.
- **확정 자산이 없는 경우**: 브랜드 적합 커스텀 느낌의 일관된 아이콘 스타일. stroke 굵기·fill 유무·라운딩이 전 화면에서 동일.
- **일관 stroke/fill**: 한 앱 안에서 어떤 아이콘은 outline, 어떤 아이콘은 solid filled가 섞이면 안 된다. 한 스타일로 통일.

## 13. Anti-Mobile-AI-Tells

아래 항목은 **프롬프트에 네거티브로 명시**하고, 생성 결과를 검수할 때 체크한다. 이것들이 이미지에 있으면 즉시 재생성한다.

- **purple-blue AI 그라데이션**: 보라-파랑 계열의 전형적인 AI 배경. DESIGN.md 팔레트에 없으면 사용하지 않는다.
- **랜덤 glass 카드**: 내용 없이 반투명 카드를 쌓는 glassmorphism 남발. 계층 정보에 근거가 있을 때만 허용.
- **ambient blob**: 배경에 둥글고 흐릿하게 떠 있는 도형·발광체.
- **가짜 차트 대시보드**: 의미 없는 바 차트·선 그래프·원형 차트가 대시보드를 채우는 패턴. 실제 데이터 구조와 무관한 장식용 숫자.
- **폰 모양 웹사이트**: 모바일 화면이 아니라 웹사이트를 폰 화면 안에 넣은 것. 탭바·세이프에어리어·앱 내비게이션이 없는 화면.
- **과한 corner radius**: 모든 요소에 크고 동그란 모서리. 시각적 무게감을 잃는다.
- **필러 카피**: 영어 elevate·unlock·revolutionize·seamless·powerful·next-level, 한국어 "혁신적인·강력한·원활한·차세대·압도적인". **카피는 DESIGN.md §1 제품 설명에서 실제 가치를 끌어낸다.**
- **가짜 브랜드명**: NovaCore·TechFlow·BuildFast·Nexus·Acme 등 자리 채우기 브랜드명. **브랜드명은 DESIGN.md §1에서.**
- **pill/badge 남발**: 화면 곳곳에 알림 뱃지·태그·pill이 과하게 붙어 있는 패턴.
- **장식용 status dot**: 리스트 셀·탭·라벨마다 앞에 붙는 의미 없는 컬러 점. 실제 상태(온라인·읽지 않음·진행 상태)를 나타낼 때만 허용.

## 14. 스타일 변주 엔진

아래 카테고리에서 **각 1개씩 골라 한 시리즈의 모든 화면에 일관 적용**한다. 화면마다 테마를 바꾸지 않는다. **Typography(폰트)와 Palette(색)는 DESIGN.md 토큰을 따른다** — 카테고리에서 고르지 않는다.

### A. Theme (전체 테마)
- `refined-light` — 밝고 깨끗한 배경, 차분한 포인트 컬러, 모던 프리미엄
- `refined-dark` — 깊은 배경, 세심한 빛 포인트, 야간 모드 프리미엄
- `clean-flat` — 평면적이고 기능 중심, 그림자 최소화
- `warm-material` — 따뜻한 재질감, 소프트한 그림자, 유기적

### B. Structure Bias (화면 구조 편향)
- `card-dominant` — 카드 기반 콘텐츠 구조, 목록보다 카드
- `list-dominant` — 스와이프 가능한 셀 목록, 정보 밀도 중심
- `canvas-hero` — 상단 큰 이미지/비주얼이 화면을 주도
- `form-focus` — 입력 필드와 컨트롤 중심

### C. Image Art Direction (이미지 방향)
- `lifestyle-subtle` — 일상적이고 자연스러운 이미지, 편집 느낌 없음
- `product-crisp` — 제품/서비스를 선명하게, 배경 절제
- `illustration-flat` — 플랫 또는 세미-플랫 일러스트
- `data-visual` — 정보 시각화가 이미지 역할을 대체

### D. Texture (텍스처)
- `none` — 텍스처 없이 순수 플랫
- `subtle-noise` — 아주 미세한 노이즈, 단색 위에 레이어
- `soft-paper` — 종이처럼 부드러운 질감
- `glass-minimal` — 아주 절제된 frosted glass (계층 근거 있을 때만)

### E. Signature Component (대표 UI 요소, 4가지 선택)
- `metric-card` — 핵심 지표를 담은 깔끔한 카드
- `progress-visual` — 진행 상태를 시각화하는 요소
- `action-sheet` — 바텀 시트 기반 행동 선택
- `profile-avatar` — 프로필 사진·아바타가 시각 앵커
- `image-carousel` — 가로 스크롤 이미지 카드 열
- `quick-action-grid` — 2×2 또는 2×3 단축 행동 그리드
- `timeline-feed` — 시간순 피드 아이템 흐름
- `comparison-toggle` — 세그먼트 또는 토글로 옵션 비교

### F. Decorative Asset (장식 자산, 2가지 선택)
- `brand-icon-accent` — DESIGN.md 확정 아이콘을 포인트 장식으로
- `color-block-header` — 상단에 색 블록으로 강조 영역
- `subtle-pattern` — 아주 작은 반복 패턴 (브랜드 모티프 기반)
- `empty-state-illo` — 빈 상태 화면용 간단한 일러스트

### G. Motion-implied (정적 이미지에서 동적 느낌, 2가지 선택)
- `scroll-indicator` — 스크롤 가능함을 암시하는 컨텐츠 끝단 처리
- `swipe-hint` — 가로 스와이프 가능함을 암시하는 카드 노출
- `tap-state-visible` — 하나의 셀/버튼이 pressed 상태로 표시
- `entrance-stagger` — 요소들이 순차 등장하는 것처럼 정렬

**Typography·Palette는 카테고리에서 고르지 않고 DESIGN.md 토큰을 그대로 쓴다.**

## 15. 텍스트 가독성·타이포·여백

**텍스트가 작으면 미완성이다.** 모바일 화면은 손에 들고 보는 것이다.

- **제목/본문/라벨 대비**: 텍스트와 배경의 명도 대비는 충분해야 한다(WCAG AA 이상). 어떤 텍스트도 배경에 묻혀서는 안 된다.
- **타입 스케일**: 제목은 크고 강하게. 바디 텍스트는 충분히 크게(너무 작으면 모바일에서 읽히지 않는다). 라벨·캡션은 작지만 대비가 충분해야 한다.
- **폰트**: DESIGN.md 토큰에서 가져온다. 한 화면에 세 가지 이상의 폰트 스타일을 섞지 않는다.
- **터치 친화**: 탭 가능한 요소는 충분히 커야 한다. 너무 작은 터치 타겟은 실제 앱처럼 보이지 않는다.
- **넉넉한 간격**: 요소 사이에 충분한 간격. 숨막히게 붙어있는 레이아웃은 미완성처럼 보인다.

## 16. 카테고리별 바이어스

앱 카테고리에 따라 아래 바이어스를 추가로 적용한다.

- **fintech**: 신뢰·차분·정밀. 차트는 필요한 것만 절제해서. 색은 과하지 않게. 숫자의 계층이 명확.
- **health**: 차분하고 구조적. 메트릭 계층이 읽힘. 부드럽지만 정밀한 느낌. 스트레스 주지 않는 색 사용.
- **productivity**: 리스트·카드의 규율. 정보 밀도가 높지만 정리됨. 빈 상태와 로딩 상태 고려.
- **social**: 프로필·피드의 리듬. 이미지가 표현의 중심. 좋아요·댓글·공유 같은 상호작용 요소 명확.
- **commerce**: 브라우즈·상세·카트 흐름이 명확. 제품 이미지가 주인공. CTA가 강하고 명확. 신뢰 신호(리뷰·배지) 절제해서.
- **wellness**: 부드러운 재질감과 여백. 과밀 금지. 진정시키는 색 사용. 억압하지 않는 UI.
