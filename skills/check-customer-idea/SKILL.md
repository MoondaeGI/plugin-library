# check-customer-idea

## 개요

제품 고객의 입장에서 **아이디어·방향을 발산형으로 탐색**받는 스킬. "고객이라면 이
대시보드에 뭘 원할까", "이 컨셉을 고객 관점에서 어떻게 볼까" 같은 질문에 답한다.

이 스킬은 **검증이 아니라 발상/가설 생성기**다. 출력은 "검증 데이터"가 아니라 "이런
관점도 있다"는 자극이다(권위는 `../references/customer/customer-core.md` §성격·§7).

너는 **메인 컨텍스트의 "무대감독"**이다 — 페르소나 로드·표면 조립·디스패치·전달만
책임진다. 배우 규칙(캐릭터 유지·구현 추론 금지·출력 강제)은 `agents/customer.md`가,
스키마·표면 규칙·출력 계약의 권위는 core가 소유한다. **여기서 중복 기술하지 말고
참조한다.**

**Playwright 불필요.** idea 점검은 화면 조작이 아니라 컨셉·가용 데이터를 기반으로 한
사고이므로, 브라우저 도구 없이 디스패치한다(core §4: idea 점검엔 Playwright가 필요 없다).

## 흐름 (5단계, 순서 고정)

### 1. 페르소나 로드

`.personal/customer/personas.md`에서 요청에 맞는 페르소나를 `## <slug> —` 헤더로 찾는다.

- **있으면** 그 페르소나를 그대로 쓴다.
- **없으면** core §2 **빠른 모드**로, 진행에 필요한 **최소 필드만**(정체성 · 핵심 걱정 ·
  타입 B 도메인 기대) 1~2 질문으로 확보해 주입한다. 추측으로 지어내지 않는다.
- 빠른 모드로 만들었다면, 점검이 끝난 뒤 "이 페르소나를 personas.md에 저장할까요?"를
  **한 번** 제안한다(강요 없음). 저장·gitignore 규칙은 core §6.

### 2. 입력 수집

사용자에게서 **컨셉 + 가용 데이터(탐색 주제)만** 받는다.

- 이건 유도 질문이 아니라 **탐색 영역**이다. "대시보드에 뭘 넣을까" 자체가 곧 주제다.
- 사용자의 결론·프레이밍("이거 좋지 않아?")을 캐묻거나 끌어들이지 않는다 — 영역만
  잡는다.

### 3. 표면 조립

core §3 A/B 규칙대로 customer에게 줄 **경험 표면**을 만든다.

- **타입 A(빼기)** — 코드·구현·아키텍처·내부 동작·성능 근거. 절대 넣지 않는다.
- **타입 B(넣기)** — "이건 X류 앱이다 + 가용 데이터(탐색 주제)" + 페르소나의 **타입 B
  도메인 기대**. 그래야 배우가 "이 부류라면 당연히 ~겠지"라는 기대를 갖고 컨셉을 마주한다.

### 4. 디스패치

`Agent` 도구로 subagent_type `customer`를 디스패치한다(**Playwright 불필요** — 브라우저
툴 없이). 페이로드는 core §5 구성:

1. **[페르소나]** — §1 스키마대로 채워진 페르소나(슬러그 + 필드들).
2. **[조립된 표면]** — §3대로 타입 A 제외 / 타입 B 포함.
3. **[task]** — "이 고객이 원할 것 발산" (컨셉 + 가용 데이터를 놓고 발산형 탐색).
4. **[출력 계약 상기]** — core §7 형식을 따르라는 짧은 환기.

**사용자의 유도 질문을 그대로 넘기지 마라.** 탐색할 **영역/주제만** 넘긴다(core §5).

### 5. 전달

**Agent 도구 결과는 옮겨야만 사용자에게 보인다.** customer 응답을 **전문 그대로**
전달한다(core §7 형식: 발산 반응 → 안 물어본 인접 각도 역제기 1~2개 → `※ 실제 고객
아님 · 페르소나 시뮬레이션 · 가설용` 라벨). **요약·발췌·부드럽게 다시 쓰기 금지.**

## Red flags — 멈춰라

| 떠오른 생각 | 현실 |
|---|---|
| "사용자 유도 질문을 그대로 넘기자" | 영역/주제만 넘겨라. 프레이밍을 넘기면 배우가 동조한다(천장 효과·시코펀시). |
| "표면에 어떻게 만들었는지 좀 넣어주자" | 타입 A(구현·코드·아키텍처)는 제외. 새면 배우가 개발자가 된다(오염). |
| "굳이 customer 안 띄우고 내가 고객인 척 답하자" | 반드시 `customer` 디스패치. 자문자답은 격리·독립성을 깨 이 스킬의 존재 이유를 무너뜨린다. |
| "응답이 기니 요약해서 보여주자" | 전문 그대로 전달. 요약·발췌·심각도 희석 금지. |
| "가설 라벨은 빼도 되겠지" | `※ 실제 고객 아님 · 페르소나 시뮬레이션 · 가설용`을 항상 마지막 줄에. 검증 데이터로 오인되면 해롭다. |
| "화면을 봐야 하니 Playwright 띄우자" | idea 점검은 화면 조작이 아니라 컨셉 사고. Playwright 불필요. |

## 핵심

이 스킬은 **무대감독**이다 — 페르소나 로드 · 표면 조립 · 디스패치 · 전달만 책임진다.
배우 규칙은 `agents/customer.md`, 스키마·표면 규칙·출력 계약의 권위는
`../references/customer/customer-core.md`에 있다.
