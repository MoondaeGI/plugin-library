# show-weekly-report

## 개요

현재 git 저장소의 **내 커밋**만 모아, 이번 주(기본)나 지정한 기간 동안 무슨
작업을 했는지 **개발을 모르는 의사결정자도 빠르게 훑어볼 수 있게** 주제별로
묶은 한국어 요약으로 보여준다. 커밋 내역만 본다 — diff 본문은 읽지 않는다.

**대상 독자는 비개발자 대표님이다.** 전문 용어·내부 스킬명·파일 경로·구현
세부는 빼고, "이번 주에 뭘 했는가"만 직관적으로 보이게 한다.

## 입력 (인자)

- **인자 없음** → 이번 주 월요일 00:00 ~ 지금 (기본값).
- **인자 있음** → git `log`에 그대로 넘기는 기간 표현.
  - 예: `2026-06-01..`, `--since="3 days ago"`, `2026-06-01..2026-06-07`.

## 흐름

1. **저장소 확인** — git 저장소가 아니면 안내하고 멈춘다.
2. **작성자 확인** — `git config user.email`로 내 이메일을 얻는다(작성자 한정용).
3. **기간 결정** — 인자가 없으면 오늘 날짜에서 **이번 주 월요일**을 계산한다
   (예: 오늘이 금 06.12면 월요일은 06.08 → `--since="2026-06-08 00:00"`).
   인자가 있으면 그 표현을 그대로 쓴다.
4. **수집** — 아래 명령으로 커밋 메시지와 파일 변경 통계를 한 번에 모은다:

   ```
   git log --since="<시작>" --author="<내 이메일>" --stat \
     --date=format:"%m.%d" --pretty=format:"%n=== %ad %s%n%b"
   ```

   - 인자로 기간을 받았으면 `--since=...` 자리에 그 표현(또는 `A..B` 범위)을 둔다.
   - 출력이 크면 먼저 압축 목록(`--pretty=format:"%ad %s"`)으로 전체 주제를
     훑은 뒤, 필요한 묶음만 `--stat`으로 확인한다.
5. **분류·요약** — 커밋을 주제별로 묶고, 바뀐 파일 경로로 "어느 부분"인지
   판단해 **비개발자 눈높이**로 옮긴다. (아래 "출력 형식" 규칙을 따른다.)
6. **출력** — 대화창에 마크다운으로 직접 출력한다. **파일로 저장하지 않는다.**

## 멘탈 모델 (먼저 이걸 정한다)

**"대표님께 30초 동안 구두로 보고한다"** 고 생각하라. 대표님은 *무엇을 했고
그게 무슨 의미인지*만 궁금하다. 서버를 어떻게 연결했고 좌표를 어떻게 변환했는지
같은 **내부 동작은 한 단어도 듣고 싶어 하지 않는다.** 보고서는 짧을수록 좋다 —
한눈에 안 들어오면 실패다.

커밋을 묶을 때 **"이건 어떻게 만들었나" 류 커밋(서버 연결·라우팅·좌표 변환·
세션·워치독·하트비트·마스크 인코딩·합성 알고리즘 등)은 절대 별도 줄로 올리지
말고, 그 기능의 상위 한 줄에 흡수**시킨다. 올릴지 말지 헷갈리면 빼라.

## 출력 형식

맨 위에 기간 헤더 한 줄, 그 아래 주제별 중첩 불릿:

```
## 이번 주 작업 (06.08~06.12)

- **이미지 부분 수정 기능 구현** (06.09~06.10)
  - 원하는 영역만 골라 고치는 도구 추가 (06.09)
  - 색칠하듯 영역을 지정하는 방식 추가 (06.10)
    - 확정 후 자동 저장·정리까지 마무리 (06.10)
- **사용자(고객) 관점 점검 도구 구현** (06.09)
- **아이디어 사전 검증 도구 구현** (06.08)
```

규칙:

- **비개발자 말로 옮긴다(가장 중요).** 기준: *우리 대표님(개발 모름)이 읽고
  바로 이해되는 단어인가?* 아니면 쉬운 말로 바꾸거나 빼라. 영어 약어·기술
  명사·내부 스킬명·파일/변수 이름·`§`·`R번호` 같은 내부 기호는 **그대로 쓰지
  않는다.** 괄호로 원어를 병기하지도 않는다(`(--control-h-*)` 금지).
  - 예: `image-edit-region 스킬` → "이미지 부분 수정 기능",
    `favicon/워드마크/락업` → "로고·아이콘", `워치독/오버레이 provider 층` →
    (구현 디테일이라 **삭제**), `React/Next 컴포넌트로 export` → "디자인을 실제
    화면으로 바꾸는 기능", `--control-h-* 토큰화` → "화면 요소 크기 통일".
  - 판단이 서지 않는 기술 디테일은 **올리지 말고 버린다.** 대표님은 "무엇을
    했는지"만 알면 된다.
- **간결하게, 큰 덩어리로 묶는다.** 상위 항목은 **3~6개**, 전체 줄 수는 대략
  **12줄 이내**를 목표로 한다. 커밋 하나당 한 줄로 풀지 말고, 비슷한 일은 한
  갈래로 합친다.
- **기본 깊이는 1단계, 필요하면 2단계.** 3단계는 거의 쓰지 않는다(허용은 하되
  예외적). 하위 항목이 구현 디테일이 되려 하면 → 그 줄을 지우고 상위에 흡수한다.
- **모든 깊이의 항목에 날짜를 붙인다.** 단일 날짜는 `(MM.DD)`, 여러 날짜에
  걸치면 `(MM.DD~MM.DD)`. 상위 항목 날짜는 그 하위들을 아우르는 범위로 잡는다.
- 큰 주제(상위 항목)는 **굵게** 표시한다.

## 출력 전 자가 점검 (필수)

보고서를 내보내기 직전, 작성한 텍스트를 한 줄씩 다시 훑으며 확인한다:

1. **모든 줄에 날짜가 있는가?** 깊이와 상관없이 **모든** 불릿 끝에 `(MM.DD)`
   또는 `(MM.DD~MM.DD)`가 붙어야 한다. 하위 항목이 상위와 날짜가 같더라도
   생략하지 말고 그대로 붙인다. 빠진 줄이 하나라도 있으면 채운다.
2. **새어 나온 기술 용어가 없는가?** 아래 단어가 하나라도 남아 있으면 쉬운
   말로 바꾸거나 그 줄을 삭제한다. *대표님이 모르는 단어 = 제거 대상.*
   - 금지어 예(이 외에도 영어·약어 전부): `React`/`Next`/`JS`, `컴포넌트`,
     `토큰`, `토스트`/`팝업 인프라`, `마크다운`, `favicon`, `PNG`/`SVG`,
     `CSS`, `API`, `마스크`, `placeholder`, `워크플로`, `인프라`, `라우팅`,
     `세션`, `서버`. → 이런 단어가 보이면 그 줄을 비개발자 말로 다시 쓰거나
     통째로 지운다. (`React/Next로 내보내기` → "디자인을 실제 화면으로 바꾸는
     기능", `favicon은 PNG로 통일` → "아이콘 만드는 방식 단순화")
3. **상위 항목이 3~6개, 전체 12줄 이내인가?** 넘으면 합쳐서 줄인다.
4. **3단계까지 내려간 줄이 있는가?** 있으면 그게 정말 필요한지 의심하고, 구현
   디테일이면 지워 상위에 흡수한다.

네 가지가 모두 통과해야 출력한다.

## 엣지 케이스

- **해당 기간 커밋 0건** → "이번 기간 커밋이 없습니다"라고만 안내한다.
- **git 저장소 아님** → 안내하고 멈춘다.
- **커밋이 아주 많음(50+)** → 주제 묶음 위주로 압축하고 사소한 커밋은 합쳐서
  표현한다. 묶다가 빠진 게 있으면 그 사실을 한 줄로 알린다.

## 흔한 실수

| 실수 | 바로잡기 |
|---|---|
| 커밋을 1:1로 그대로 나열 | 주제별로 묶어 "뭘 했는지"로 요약한다. |
| 상위 항목이 8개+로 장황 | 큰 덩어리 3~6개로 합친다. |
| 스킬명·파일 경로·`§`·전문 용어를 그대로 노출 | 비개발자 말로 옮긴다. |
| 영어 약어·변수명을 괄호로 병기(`(--control-h-*)`) | 원어 병기도 금지. 쉬운 말로 바꾸거나 뺀다. |
| 애매한 기술 디테일을 억지로 올림 | 모르면 올리지 말고 버린다. |
| 상위 항목에만 날짜를 달고 하위는 비움 | 모든 깊이에 날짜를 붙인다. |
| 작성자 한정을 빼고 남의 커밋까지 집계 | `--author`로 내 이메일만. |
| diff 본문까지 읽어 장황해짐 | 메시지 + `--stat`까지만. |
| 보고서를 파일로 저장 | 대화창에 직접 출력만 한다. |
