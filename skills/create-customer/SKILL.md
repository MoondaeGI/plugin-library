# create-customer

## 개요

customer 페르소나를 **작정하고 저작·수정·열람하는 단독 진입점**. check-customer-ux·check-customer-idea가 인라인 "빠른 모드"로 점검 직전에 최소 필드만 급조하는 것과 달리, 이 스킬은 "꼼꼼 모드"로 **진한 페르소나를 미리 쌓아 둔다.**

페르소나 스키마와 절차의 권위는 `../references/customer/customer-core.md`에 있다. 이 스킬은 그 코어를 **참조만** 한다(복붙 금지·DRY):

- 페르소나 스키마(필드 정의·저장 형식) — core **§1**.
- 꼼꼼 모드 인터뷰 절차 — core **§2 (꼼꼼 모드)**.
- 저장 경로·gitignore prompt — core **§6**.

**왜 꼼꼼하게 캐는가:** 변별력 있는 페르소나가 곧 평가 품질이다. "38세 간호사" 한 줄로 끝낸 얄팍한 페르소나는 누구에게 물어도 같은 일반론만 돌려준다. 걱정·맥락·도메인 기대·회의 지점까지 구체를 끝까지 캐낸 페르소나라야 check-customer-* 가 변별력 있는 반응을 끌어낸다. 이 스킬의 핵심은 **구체성을 끝까지 캐는 것.**

## 모드 분기

사용자 요청에 따라 셋 중 하나로 분기한다. 시작 시 `.personal/customer/personas.md`를 먼저 읽어(있으면) 어떤 슬러그가 이미 있는지 파악한다.

### 1. 신규 저작

core **§2 꼼꼼 모드** 인터뷰로 스키마 **전 필드**를 채운다.

- **한 번에 하나씩** 묻는다. 한꺼번에 폭격하지 않는다.
- **추측 금지.** 사용자가 안 준 필드를 지어내지 않는다 — 물어본다.
- 채울 필드(core §1): `slug` · 한 줄 정체성 · 가장 큰 걱정 1~2 · 맥락 · 타입 B 도메인 기대 · 회의 지점.
- 한 줄로 얕게 답하면 한 번 더 파고든다("그 걱정이 구체적으로 어떤 상황에서 터지나요?"). 변별력이 곧 품질이다.
- 다 채우면 아래 **저장 절차**로 personas.md에 append.

### 2. 수정

기존 페르소나를 **slug로 찾아** 해당 블록만 갱신한다.

- personas.md에서 `## <slug> —` 헤더로 대상 블록을 찾는다(core §1 저장 형식).
- 어느 필드를 바꿀지 확인하고, 빈 필드를 채우는 경우에도 **추측 금지** 원칙은 동일하게 적용 — 물어본다.
- **그 한 블록만** 교체한다. 다른 페르소나 블록은 건드리지 않는다(불변 — 나머지 그대로 유지).

### 3. 리스트 / 열람

- personas.md의 `## <slug> — <한 줄 정체성>` 헤더들을 훑어 **목록**을 보여준다(슬러그 + 정체성 한 줄).
- 사용자가 한 명을 지목하면 그 페르소나의 **전 필드를 전문 그대로** 표시한다.
- personas.md가 없거나 비어 있으면 그 사실을 알리고 신규 저작을 제안한다.

## 저장 절차

상세 규칙은 core **§6**에 있다 — 여기서 중복 기술하지 않는다. 요지만:

- 경로: `.personal/customer/personas.md`.
- 저장 형식: core §1의 `## <slug> — <한 줄 정체성>` 헤더 + 필드 불릿 블록.
- `.personal/`을 **새로 만들 때만** gitignore 1회 prompt(core §6). 먼저 `.gitignore`를 grep으로 확인하고, 이미 있거나 한 번 물었으면 **재nag 없음**. `.personal/`이 이미 있으면 prompt 없이 그 안에 저장한다.
- 신규는 파일 끝에 `##` 블록으로 append, 수정은 해당 블록만 교체.

## 마무리 안내

저장이 끝나면 사용자에게 다음 출구를 안내한다:

> 이제 `/check-customer-ux <URL> <영역>` 또는 `/check-customer-idea <컨셉>`으로 이 페르소나에게 직접 물어볼 수 있습니다.

## Red flags — 멈춰라

| 떠오른 생각 | 현실 |
|---|---|
| "안 준 필드는 그럴듯하게 채워 넣자" | 추측 금지. 모르면 **물어봐라**(core §2 꼼꼼 모드). |
| "한 줄짜리 페르소나로 끝내자" | 얄팍하면 일반론만 나온다. **변별력이 곧 품질** — 구체를 끝까지 캐라. |
| "스키마·저장·gitignore 규칙을 여기 복붙하자" | 권위는 core에 있다. **참조하라**(DRY). 중복 기술 금지. |
| "수정하는 김에 다른 블록도 손보자" | 지목된 한 블록만 교체. 나머지는 불변으로 유지. |
| "질문 다섯 개 한꺼번에 던지자" | 한 번에 하나씩. 폭격하면 답이 얕아진다. |
