# check-customer-ux

## 개요

제품 고객의 입장에서 **UX 불편을 점검**받는 스킬. "이 결제 플로우 고객이 써보면
어디서 막힐까", "이 페이지 처음 보는 고객이 헤매지 않을까" 같은 질문에 답한다.

이 스킬은 **검증이 아니라 발상/가설 생성기**다. 출력은 "검증 데이터"가 아니라 "이런
관점도 있다"는 자극이다(권위는 `../references/customer/customer-core.md` §성격·§7).

너는 **메인 컨텍스트의 "무대감독"**이다 — 페르소나 로드·표면 조립·디스패치·전달만
책임진다. 배우 규칙(캐릭터 유지·구현 추론 금지·출력 강제)은 `agents/customer.md`가,
스키마·표면 규칙·출력 계약의 권위는 core가 소유한다. **여기서 중복 기술하지 말고
참조한다.**

**UX는 멈춘 스크린샷이 아니라 흐름·전환·조작 중 마찰에서 드러난다.** 그래서 가능하면
customer가 **인간 채널 Playwright로 직접 조작하며 탐색**하게 한다. Playwright는 옵셔널
의존성이다 — 없으면 폴백으로 정상 동작한다(core §4).

## 흐름 (6단계, 순서 고정)

### 1. 페르소나 로드

`.personal/customer/personas.md`에서 요청에 맞는 페르소나를 `## <slug> —` 헤더로 찾는다.

- **있으면** 그 페르소나를 그대로 쓴다.
- **없으면** core §2 **빠른 모드**로, 진행에 필요한 **최소 필드만**(정체성 · 핵심 걱정 ·
  타입 B 도메인 기대) 1~2 질문으로 확보해 주입한다. 추측으로 지어내지 않는다.
- 빠른 모드로 만들었다면, 점검이 끝난 뒤 "이 페르소나를 personas.md에 저장할까요?"를
  **한 번** 제안한다(강요 없음). 저장·gitignore 규칙은 core §6.

### 2. 입력 모드 결정 (core §4)

세 모드 중 하나로 표면을 잡는다. **Playwright MCP는 하드 의존이 아니다** —
미등록이어도 아래 폴백으로 정상 동작한다.

| 조건 | 모드 |
|---|---|
| URL 있음 + Playwright MCP 등록됨 | **실사용 탐색** — customer가 직접 조작하며 돌아다닌다(최선). |
| 스크린샷 첨부됨 | 그 스크린샷을 표면으로 사용한다. |
| 둘 다 없음 | **"시각 디테일은 추정"** 경고를 사용자에게 **먼저 띄우고** 진행한다. |

### 3. 영역만 받기

사용자에게서 점검할 **영역**("결제 플로우" 같은)만 받는다.

- 이건 유도 질문이 아니라 **탐색 영역**이다. "결제 플로우 어디서 막힐까" 자체가 곧 주제다.
- 사용자의 결론·프레이밍("이거 너무 헷갈리지 않아?")을 **캐묻거나 넘기지 않는다** —
  영역만 잡는다(core §5). 프레이밍을 넘기면 배우가 동조한다(천장 효과·시코펀시).

### 4. 표면 조립

core §3 A/B 규칙대로 customer에게 줄 **경험 표면**을 만든다.

- **타입 A(빼기)** — 코드·구현·아키텍처·내부 동작·성능 근거·DOM·셀렉터. 절대 넣지 않는다.
- **타입 B(넣기)** — "이건 X류 앱이다" + 페르소나의 **타입 B 도메인 기대**. 그래야 배우가
  "이 부류라면 당연히 ~겠지"라는 기대를 갖고 화면을 마주한다.
- **모드별 표면 본체**: 실사용 모드면 **URL**을, 스크린샷 모드면 **이미지**를 표면에
  포함한다. 추정 모드면 본체 없이 타입 B 멘탈모델만으로 진행한다(시각 디테일은 추정).

### 5. 디스패치

`Agent` 도구로 subagent_type `customer`를 디스패치한다. 페이로드는 core §5 구성:

1. **[페르소나]** — §1 스키마대로 채워진 페르소나(슬러그 + 필드들).
2. **[조립된 표면]** — §3대로 타입 A 제외 / 타입 B 포함. 모드별 본체(URL·이미지) 포함.
3. **[task: UX 영역]** — "직접 조작하며 이 영역을 써보고 불편을 짚어라"(영역만).
4. **[출력 계약 상기]** — core §7 형식을 따르라는 짧은 환기.

**실사용 모드면 인간 채널 Playwright 툴만 허용한다(core §4 화이트리스트).** 실제 고객은
눈과 손으로만 제품을 쓰므로 도구도 거기 맞춘다 — 타입 A 차단이 텍스트 큐레이션이 아니라
툴 권한 레벨에서 구조적으로 강제된다.

- **허용 (눈·손, 17종):** `browser_navigate`, `browser_navigate_back`,
  `browser_take_screenshot`, `browser_snapshot`, `browser_click`, `browser_type`,
  `browser_press_key`, `browser_hover`, `browser_select_option`, `browser_wait_for`,
  `browser_resize`, `browser_tabs`, `browser_handle_dialog`, `browser_file_upload`,
  `browser_drag`, `browser_drop`, `browser_fill_form`
- **금지 (구현 X-ray = 타입 A):** `browser_evaluate`, `browser_run_code_unsafe`,
  `browser_console_messages`, `browser_network_request`, `browser_network_requests`

(스크린샷·추정 모드면 브라우저 툴 없이 디스패치한다. 등록 시 실제 툴 이름은
`mcp__<등록명>__browser_*` 형태 — core §4 메모.)

**사용자의 유도 질문을 그대로 넘기지 마라.** 점검할 **영역만** 넘긴다(core §5).

### 6. 전달

**Agent 도구 결과는 옮겨야만 사용자에게 보인다.** customer 응답을 **전문 그대로**
전달한다(core §7 형식: 불편 지점 → 안 물어본 인접 각도 역제기 1~2개 → `※ 실제 고객
아님 · 페르소나 시뮬레이션 · 가설용` 라벨). **요약·발췌·부드럽게 다시 쓰기 금지.**

## Red flags — 멈춰라

| 떠오른 생각 | 현실 |
|---|---|
| "사용자 유도 질문을 그대로 넘기자" | 영역만 넘겨라. 프레이밍을 넘기면 배우가 동조한다(천장 효과·시코펀시). |
| "표면에 어떻게 만들었는지 좀 넣어주자" | 타입 A(구현·코드·아키텍처·DOM·셀렉터)는 제외. 새면 배우가 개발자가 된다(오염). |
| "customer한테 evaluate/network/console도 열어주자" | 인간 채널만(허용 17종). 그 셋은 구현 X-ray=타입 A라 금지. |
| "스크린샷 한 장으로 흐름까지 판단하자" | UX는 흐름·전환에서 드러난다. 가능하면 실사용 탐색. 정적이면 그 한계를 인지하고 짚는다. |
| "굳이 customer 안 띄우고 내가 고객인 척 답하자" | 반드시 `customer` 디스패치. 자문자답은 격리·독립성을 깨 이 스킬의 존재 이유를 무너뜨린다. |
| "추정 모드인데 그냥 진행하자" | 시각 디테일이 추정임을 **먼저** 사용자에게 경고하고 진행한다. |
| "응답이 기니 요약해서 보여주자" | 전문 그대로 전달. 요약·발췌·심각도 희석 금지. |
| "가설 라벨은 빼도 되겠지" | `※ 실제 고객 아님 · 페르소나 시뮬레이션 · 가설용`을 항상 마지막 줄에. 검증 데이터로 오인되면 해롭다. |

## 핵심

이 스킬은 **무대감독**이다 — 페르소나 로드 · 표면 조립 · 디스패치 · 전달만 책임진다.
idea 스킬과 다른 점은 **입력 3모드(실사용/스크린샷/추정)와 인간 채널 툴 제한**뿐이다.
나머지(로드·표면 조립·전달)는 형제 스킬과 같은 구조다. 배우 규칙은 `agents/customer.md`,
스키마·표면 규칙·출력 계약의 권위는 `../references/customer/customer-core.md`에 있다.
