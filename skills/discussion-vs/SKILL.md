# discussion-vs

## 개요

"논의 단계" 스킬. Claude가 본인 의견을 내고 → **독립적인** 악마의 변호인이 *사용자 입력과 Claude 의견 둘 다*를 공격하고 → Claude가 그 공격에 응답한다. 핵심 가치는 **독립성** — 같은 호흡에 자기가 자기를 까면 "내 의견 방어" 편향이 낀다.

**핵심 규칙: 비판을 네가 직접 쓰지 마라. `devils-advocate` 서브에이전트(subagent_type `personal:devils-advocate`)를 디스패치하고, 그 결과를 그대로 전달하라.** 자가 작성 비판은 이 스킬의 존재 이유를 무너뜨린다.

## 흐름 (3단계, 순서 고정)

1. **내 의견** — 주제에 대한 솔직한 입장 + 핵심 근거를 간결히. 얼버무리지 말고 진짜 네 입장을.

2. **딴지 (독립 비판)** — `devils-advocate` 서브에이전트를 Agent 도구로 디스패치한다. 검증 대상 **둘 다** 넘긴다:
   - ① 사용자의 원래 입력·프레이밍
   - ② 방금 1단계에서 낸 내 의견 (그대로 인용)

   **Agent 도구 결과는 사용자에게 자동으로 보이지 않는다 — 네가 옮겨야만 보인다.** 그러므로 서브에이전트 응답을 **전문 그대로 출력**한다(steelman / 심각도순 반론 / 인정하는 부분 / 가장 위험한 단일 허점 / 종합 판정). 요약·생략·발췌 금지, 다시 쓰거나 부드럽게 만들지 않는다.

3. **종합 (응답)** — 딴지에 응답한다: 어떤 🔴를 인정해 의견을 바꾸는지, 어떤 반론은 버티는지(근거), 최종적으로 어디 서는지.

   **이 단계는 의견 전달까지만이다.** 인정한 반론이 있어도 산출물(코드·파일·문서)을 직접 수정하지 않는다. 수정 여부·범위는 사용자가 결정한다 — 필요하면 "이러이러하게 고치는 게 좋겠다"고 **제안만** 하고 멈춘다.

   **스킬은 이 3단계 출력으로 종료된다.** 이후 사용자 턴은 이 스킬의 제약(수정 금지 등)을 받지 않는 일반 대화이며, 그때 사용자가 수정을 지시하면 평범한 새 요청으로 처리한다.

## 서브에이전트 디스패치

두 대상을 명시한 단일 프롬프트로 넘긴다. 예:

> 다음 두 가지를 **모두** 검증 대상으로 압박하라.
> ① 사용자 입력: "{사용자 원래 프롬프트}"
> ② 내(Claude) 의견: "{1단계에서 낸 의견}"

## Red flags — 멈춰라

| 떠오른 생각 | 현실 |
|---|---|
| "내가 직접 반대 의견 써주면 되지" | 핵심은 독립성. 자가 비판엔 자기 의견 방어 편향이 낀다. 반드시 서브에이전트 디스패치. |
| "내 의견만 까면 되겠지" | 사용자 입력 프레이밍도 틀릴 수 있다. **둘 다** 대상. |
| "딴지 출력을 좀 다듬어/요약해 보여주자" | Agent 결과는 옮겨야만 보인다. 전문 그대로 출력, 요약·심각도 희석 금지. |
| "인정했으니 내친김에 바로 고쳐버리자" | 3단계는 의견·제안까지만. 산출물 수정은 사용자 결정. 멋대로 고치지 않는다. |
| "의견 없이 바로 딴지부터" | 의견(1) → 딴지(2) → 응답(3) 순서를 지킨다. |

## 흔한 실수

- 1단계(의견)를 건너뛰고 바로 비판으로 감 → 검증할 대상이 없다.
- 서브에이전트에 대상을 하나만 넘김 → 둘 다 넘겨야 한다.
- 서브에이전트를 안 띄우고 즉석에서 비판을 지어냄 → 독립성 상실.
- 서브에이전트 응답을 요약·발췌만 하고 전문을 안 보여줌 → 사용자가 실제 딴지 내용을 못 본다.
- 3단계에서 반론을 인정한 뒤 곧장 산출물을 수정함 → 수정은 사용자 결정. 제안에서 멈춘다.
