# 웹 아트디렉션 레퍼런스

## 0. 이 문서의 목적 / 사용법

이 문서는 `design-image-web` 스킬이 프롬프트를 구성할 때 읽는 아트디렉션 가드레일이다. 추상적인 디자인 이론이 아니라 **이미지 모델이 실제로 적용할 수 있는 구체적·렌더 가능한 형태 지시**만 담는다. 목표 품질 기준은 "그럴듯한 AI 이미지"가 아니라 **awwwards급 프리미엄 풀페이지 목업 레퍼런스 이미지**다.

**대원칙: 모든 값(색·폰트·카피·브랜드명)은 DESIGN.md 토큰에서 가져온다.** 이 문서는 형태·구도·리듬·금지 패턴을 정의하며, 값을 창작하지 않는다. 둘이 충돌하면 DESIGN.md가 정답이다.

사용법: §1 핵심 디렉티브로 이미지 목적을 확인 → §2에서 페이지 무드를 매핑(단, DESIGN.md §3이 우선) → §3 조합형 변주 엔진으로 방향 조합(단, Typography·Palette는 DESIGN.md 토큰 고정) → §4 풀페이지 구성 규칙으로 한 컴프의 내러티브를 설계 → §5 anti-AI-slop 카탈로그를 네거티브 프롬프트로 활용 → §6 히어로 규칙으로 구도 결정 → §7 팔레트 규율로 전 페이지 일관성 유지 → §8 포맷·발산 규칙 확인 → §9 품질 체크리스트로 최종 판정.

## 1. 핵심 디렉티브

이 스킬이 만드는 이미지는 **HTML 구현(`design-html-prototype`) 직전, 페이지 룩을 탐색하기 위한 풀페이지 목업 레퍼런스 이미지**다. 감상용 아트워크가 아니다.

- **한 페이지를 한 맥락으로**: 하나의 1:3 컴프 안에 nav→히어로→콘텐츠 섹션→footer가 위에서 아래로 자연스럽게 이어져야 한다. 섹션 조각이 아니다.
- **개발자·코딩 모델이 보고 재구축할 수 있어야 한다**: 레이아웃 계층·간격·타입 스케일·CTA 우선순위가 이미지 안에서 읽혀야 한다. "그리드가 어떻게 나뉘는가", "H1이 어디 있는가", "버튼이 몇 개이고 어디 있는가"를 파악할 수 있어야 한다.
- **레이아웃이 읽혀야 한다**: 컬럼 구분, 여백 크기, 섹션 경계가 명확해야 한다.
- **계층이 읽혀야 한다**: 헤드라인 → 서브헤드 → 바디 → CTA의 시각적 크기 차이가 눈에 보여야 한다.
- **브랜드 요소가 실제처럼 느껴져야 한다**: DESIGN.md의 실제 색, 실제 폰트, 실제 제품명이 들어간다. Acme Corp, 플레이스홀더 텍스트, 재고 사진은 없다.
- **구현 근거가 있는 결정만**: 장식 때문에 넣은 요소가 아니라 정보 계층에서 나온 결정이어야 한다.

## 2. 브리프 → 페이지 무드 매핑

**DESIGN.md §3 시각 방향이 항상 우선한다.** 사용자가 방향을 명시했으면 아래 표를 덮어씌운다. DESIGN.md §3이 없을 때만 브리프 키워드로 아래를 참고한다.

| 방향 키워드 | 히어로 스케일 | 배경 모드 | 구도 바이어스 | 페이지 무드 |
|---|---|---|---|---|
| **minimalist** | mid(50~60 vh) | 흰 또는 오프화이트·얕은 그레이 | 중앙 세로축 정렬, 넓은 좌우 여백 | 제한된 컬러 포인트, 날카로운 그리드, 절제된 섹션 밀도 |
| **editorial** | giant(80 vh↑) | 깊은 어두운 배경 또는 풀블리드 사진 | 비대칭, 왼쪽 하단 앵커, 큰 타입 | 대형 타이포가 주인공, 이미지는 배경, 페이지 전체에 강한 리듬 |
| **cinematic** | giant | 풀블리드 사진·영상 분위기 | image-as-canvas, 타입은 오버레이 | 강한 분위기, 빛·안개·깊이감, 한 페이지가 하나의 분위기 |
| **SaaS** | mid | 밝은 배경, UI 스크린샷·다이어그램 | stacked-center 또는 centered over image | 기능 증거, 소프트 섀도우 카드, CTA 우선, 정보 밀도 중간 |
| **agency** | giant | 검정 또는 매우 어두운 배경 | 비대칭, 대담한 타입, 대각 구성 | 강한 대비, 페이지 전체에 에너지, 의미 있는 큰 타입 |
| **ecommerce** | mid~mini | 밝은 흰 배경 또는 제품 사진 | image-as-canvas, 텍스트는 위 또는 하단 | 제품 강조, 빠른 CTA, 신뢰 신호, 스크롤 내러티브 명확 |

## 3. 조합형 변주 엔진 (페이지 단위)

아래 카테고리에서 **각 1개씩 골라 한 페이지 전체에 일관 적용**한다. 섹션마다 테마를 바꾸지 않는다. 조합이 한 페이지의 아이덴티티를 만든다.

**일관 적용은 Theme·Background·Palette·Typography 같은 페이지-레벨 결정에 해당하며, Page Rhythm System·Signature Component·구도는 §4대로 한 페이지 안에서 변주한다.**

### A. Theme Paradigm (전체 테마)
- `refined-dark` — 깊은 배경, 세심한 빛 포인트, 프리미엄 분위기
- `clean-light` — 밝은 배경, 넓은 여백, 기능 중심
- `editorial-mono` — 강한 흑백 대비, 타이포 주도
- `ambient-tonal` — 저채도 톤온톤, 배경과 전경의 경계가 부드러운

### B. Background Character (배경 성격)
- `full-bleed-photo` — 사진이 배경 전체를 채움, 텍스트는 오버레이
- `solid-brand` — DESIGN.md 토큰 배경색 단색 (값은 DESIGN.md에서)
- `gradient-subtle` — DESIGN.md 토큰 색 기반 저채도 그라디언트 (팔레트 내에서만 — §7 규율 참고)
- `texture-minimal` — 아주 미세한 노이즈·그레인, 단색 위에 레이어
- `split-field` — 배경이 두 영역으로 나뉨 (비율은 콘텐츠 논리에 따라)

### C. Hero Architecture (히어로 구조)
- `centered-over-image` — 이미지/영상 위에 텍스트 중앙 정렬
- `bottom-left-anchor` — 헤드라인이 왼쪽 하단, 이미지는 우상단 또는 배경
- `stacked-center` — 텍스트·CTA가 세로로 쌓이고 중앙 정렬, 이미지는 배경 또는 하단
- `image-as-canvas` — 이미지가 캔버스 전체, 텍스트는 레이어 위
- `inverted-classic` — 이미지 왼쪽, 텍스트 오른쪽 (일반 left-text/right-image의 반전)
- `full-width-type` — 타입이 거의 전체 폭을 차지, 이미지는 없거나 배경에만

**§6 히어로 규칙과 함께 적용한다.** 기본값인 `text-left / image-right` 구도는 위 목록에 없다 — 반사적으로 선택하지 않는다.

### D. Page Rhythm System (한 페이지 안의 섹션 배열 · 밀도 리듬)
한 컴프 안에서 섹션들을 어떻게 배열하고 리듬을 만드는지.
- `alternating-focus` — 섹션마다 이미지·텍스트 초점이 교대하며 페이지가 숨을 쉼
- `card-grid-break` — 카드 그리드 섹션과 풀블리드 섹션이 교차해 긴장을 풀어줌
- `type-led-rhythm` — 텍스트 크기·밀도 변주가 리듬을 만들고, 이미지는 악센트 역할

### E. Signature Component (대표 UI 요소, 4가지 선택)
- `bento-asymmetric` — 비균등 크기의 bentobox 그리드
- `oversized-stat` — 큰 숫자가 시각적 앵커 (단, 의미 있는 수치만 — §5 content-slop 참고)
- `icon-text-pair` — DESIGN.md 아이콘셋 + 텍스트 쌍으로 기능 목록
- `testimonial-pull` — 큰 인용문이 섹션을 주도
- `feature-screenshot` — 실제 UI 스크린샷 또는 다이어그램
- `horizontal-scroll-hint` — 가로 스크롤 힌트가 있는 카드 행
- `timeline-flow` — 수평 또는 수직 타임라인
- `comparison-table` — 기능 비교 테이블 (단순하고 읽기 쉽게)

### F. Motion-implied (정적 이미지에서 동적 느낌, 2가지 선택)
- `parallax-depth` — 레이어 간 깊이감이 시각적으로 암시
- `scroll-trigger-ghost` — 반투명 요소로 스크롤 진입 암시
- `hover-state-visible` — 하나의 카드/버튼이 hover 상태로 표시
- `entrance-stagger` — 요소들이 순차 등장하는 것처럼 정렬

### G. Hero Scale
- `giant` — 화면 높이의 80% 이상, 강렬한 첫인상
- `mid` — 화면 높이의 50~70%, 정보와 분위기 균형
- `mini` — 화면 높이의 40% 이하, 기능 페이지·랜딩 중간 섹션

### H. Narrative Spine (페이지 서사 흐름)
- `problem-solution` — 문제 제기 → 해결 → 증거
- `benefit-led` — 핵심 이득 → 세부 기능 → 신뢰 신호
- `showcase-first` — 제품 시각 → 설명 → CTA
- `story-arc` — 상황 → 갈등 → 전환 → 해소

### I. Second-read Moment (1가지 선택)
페이지 안 어딘가에, 사용자가 두 번 볼 때 발견하는 디테일 하나.
- `subtle-icon-accent` — 작은 아이콘 포인트
- `micro-stat` — 신뢰를 주는 작은 수치
- `background-texture` — 배경의 미세한 질감
- `ghost-ui-element` — 반투명 UI 요소

**Typography와 Palette는 카테고리에서 고르지 않고 DESIGN.md 토큰을 그대로 쓴다.**

## 4. 풀페이지 구성 규칙

한 1:3 컴프 안에서 페이지 전체를 구성하는 방법.

### 스크롤 내러티브
한 컴프 안에 **nav→히어로→콘텐츠 섹션→footer가 위→아래 자연스러운 스크롤 내러티브**로 이어져야 한다. 사용자가 게이트1에서 고른 섹션만 담는다. 각 섹션이 독립적인 이미지가 아니라 한 페이지의 위→아래 구간으로 읽혀야 한다.

### 한 페이지 안의 리듬 · 여백 · 밀도 변주
단조로운 슬랩(모든 섹션이 동일한 높이·구도·밀도로 쌓인 것)은 금지한다. 한 페이지 안에서 아래 변주를 **적어도 2가지** 적용한다:
- **밀도 변주**: 텍스트·이미지가 많은 구간 vs 여백이 지배하는 구간
- **이미지 비율 변주**: 풀블리드 구간 vs 이미지 없는 순수 텍스트 구간
- **정렬 변주**: 왼쪽 정렬 구간 vs 중앙 정렬 구간
- **스케일 변주**: 큰 히어로 구간 vs 컴팩트 피처 구간

### 일관성 유지
풀페이지 내 전 구간은 **하나의 팔레트·타입 스케일·CTA 패밀리**를 공유한다. 구간마다 테마가 바뀌면 안 된다:
- **같은 브랜드 월드**: DESIGN.md 확정 자산(로고·아이콘·ui-base)이 전 구간에 일관 적용
- **같은 타입 스케일**: H1·서브헤드·바디의 크기 비율이 구간마다 동일
- **같은 CTA 패밀리**: 버튼 스타일·크기·색이 전 구간에서 동일
- **같은 이미지 트리트먼트**: 사진 처리 방식(컬러·모노크롬·오버레이 강도)이 일관
- **같은 radius 언어**: 카드·버튼·이미지의 모서리 반경이 일관

### 히어로 구도 편향 차단
히어로에서 `text-left / image-right` 분할 구도는 반사적으로 선택하지 않는다. 아래 대안 구도 중 하나를 선택한다:

| 구도 | 적합한 경우 |
|---|---|
| `centered over image` | 풀블리드 배경에 강한 분위기가 필요할 때 |
| `bottom-left anchor` | editorial 방향, 큰 타입이 주인공일 때 |
| `stacked center` | SaaS·기능 중심, 명확한 CTA 계층이 필요할 때 |
| `image-as-canvas` | 제품/공간 이미지가 강력할 때 |
| `inverted classic` | 이미지 왼쪽·텍스트 오른쪽, 의도적 역전 |
| `full-width type` | editorial·agency, 타입이 유일한 주인공 |

## 5. Anti-AI-Slop 카탈로그

아래 항목은 **프롬프트에 네거티브로 명시**하고, 생성 결과를 검수할 때 체크한다.

### Layout Slop (레이아웃 슬롭)
- **반복 중앙정렬**: 페이지의 모든 구간 텍스트가 중앙 정렬로만 되어 있음. 왼쪽 정렬·비대칭을 섞는다.
- **동일 카드 행**: 같은 크기·같은 여백의 카드 3개가 한 행에 반복. 비균등 벤토나 교대 레이아웃으로 변주.
- **클론 좌우 블록**: 왼쪽 텍스트·오른쪽 이미지 블록이 구간마다 동일하게 반복.
- **죽은 대칭**: 좌우가 거울처럼 완벽히 대칭. 의도된 비대칭이 살아있는 레이아웃을 만든다.
- **균등 구간 높이**: 페이지 내 모든 구간이 같은 높이. 작은 구간·큰 구간을 의도적으로 섞는다.
- **split-header**: 왼쪽에 큰 헤드라인, 오른쪽 상단에 정렬 근거 없이 떠 있는 작은 설명 단락이 구간 헤더로 반복. 헤드라인 아래로 세로 스택하거나, 오른쪽 칸에 실제 비주얼·인터랙티브 요소가 올 때만 2단 헤더를 쓴다.

### Visual Slop (비주얼 슬롭)
- **purple/blue AI 그라데이션**: 보라-파랑 계열의 전형적인 AI 스타트업 배경. **DESIGN.md 팔레트에 없으면 사용하지 않는다.**
- **glow 효과**: 요소 주변에 퍼지는 빛 번짐. 팔레트 내 색이어도 과한 glow는 AI 티가 난다.
- **floating blob**: 배경에 둥글고 흐릿하게 떠 있는 도형. §3B `gradient-subtle`로 대체한다.
- **무의미한 glassmorphism**: 내용 없이 반투명 카드를 쌓는 것. glassmorphism을 쓸 때는 계층 정보에 근거가 있어야 한다.
- **과도한 입체·그림자**: 현실에 없는 3D bevel, 과장된 drop shadow. 그림자는 얕고 절제된 soft shadow만 허용.
- **스톡 사진 배경**: 출처 불명의 재고 사진. DESIGN.md 확정 자산(`ui-base.png`, `key-visual.png`)을 앵커로 사용한다.

### Typography Slop (타이포그래피 슬롭)
- **거대 헤딩 + 약소 서브**: H1이 화면을 꽉 채우는데 서브헤드가 아주 작은 캡션 크기. 계층 비율이 자연스러워야 한다.
- **그라데이션 헤드라인**: H1 텍스트 자체에 그라데이션 칠. §7 팔레트 규율의 그라데이션 텍스트 금지 항목 참고.
- **all-caps 남발**: 헤드라인·서브헤드·CTA·라벨이 모두 대문자. all-caps는 한 페이지에서 하나의 요소에만 사용한다.
- **폰트 스택 혼재**: 한 페이지 안에 세 가지 이상의 다른 폰트 스타일. DESIGN.md 타이포그래피 토큰의 폰트만 사용한다.

### Content Slop (콘텐츠 슬롭)
- **클리셰 카피**: 영어 "Unleash", "Elevate", "Revolutionize", "Seamless", "Powerful", "Next-level" 등 또는 한국어 "혁신적인", "강력한", "원활한", "차세대", "압도적인" 등의 자리 채우기. **카피는 DESIGN.md §1 제품 설명에서 실제 가치를 끌어낸다.**
- **가짜 브랜드명**: Acme, Nexus, NovaCore, TechFlow, BuildFast 등 자리 채우기용 브랜드명. **브랜드명은 DESIGN.md §1에서 가져온다.**
- **플레이스홀더 텍스트**: Lorem ipsum, "[제품명]" 브래킷. 실제 DESIGN.md 제품명·카피를 넣는다.
- **의미 없는 숫자 장식**: 배경에 크게 깔린 "100+", "10K", "99%" — 근거 없이 신뢰를 연출하는 숫자.
- **재고 사진 인물**: 전형적인 비즈니스 핸드셰이크, 노트북 앞 웃는 팀원 사진.

### Density Slop (밀도 슬롭)
- **과밀**: 한 구간에 텍스트·카드·아이콘·그래프·CTA가 동시에. 구간당 하나의 핵심 메시지.
- **카드 과부하**: 카드가 너무 많아 어느 것을 볼지 모르는 상태. 중요도 계층이 없는 균등 카드 배열.
- **여백 공포증**: 빈 공간을 채우려는 강박. 여백은 디자인 요소다 — 버리지 않는다.

### Decoration Slop (장식·메타 슬롭)
"디자인된 티"를 내려고 붙이는 의미 없는 라벨·구분자·장식 요소. 정보가 아니라 분위기용이면 뺀다.
- **eyebrow 남발**: 모든 섹션 헤드라인 위에 작은 대문자 wide-tracking 라벨(`SELECTED WORK`·`기능 소개` 류)을 반복해 같은 리듬을 찍어내는 것. 라벨 없이 헤드라인만으로 충분하며, 페이지 전체에 몇 개만 드물게 쓴다.
- **장식용 status dot**: nav 링크·리스트 행·뱃지마다 앞에 붙는 컬러 점. 실제 상태(서버 상태·재고/가용 플래그)를 나타낼 때만 드물게 허용.
- **히어로 하단 장식 스트립**: 히어로 바닥을 가로지르는 `BRAND. MOTION. SPATIAL.` 류 작은 대문자 텍스트 스트립. 실제 내비/상태 정보가 아니면 뺀다.
- **세로 회전 텍스트**: 90도 돌린 세로 라벨(`INDEX 2018-2026` 류). agency·experimental 방향이 명시적으로 요구하고 구도상 이유가 있을 때만.
- **scroll cue**: `↓ Scroll`·`Scroll to explore`·마우스휠 아이콘. 히어로를 보는 사용자는 스크롤을 안다 — 뺀다.
- **이미지 위 pill 오버레이**: 사진 위에 `Plate · 02`·`Frame XII` 류 태그·라벨을 얹는 것. 이미지는 그대로 두고, 캡션이 필요하면 이미지 아래(바깥)에 둔다.

## 6. 히어로 규칙

### 구도 기본값 차단
`text-left / image-right` 분할 구도는 반사적으로 선택하지 않는다. §4 히어로 구도 편향 차단의 대안 구도 중 하나를 선택한다.

### H1 길이
- **2~3줄이 기본값**: 간결하고 강하게.
- **6줄 이상 금지**: H1이 단락이 되는 순간 계층이 무너진다.
- 한국어 H1은 1줄당 10~14자 기준으로 줄 수를 계산한다.

### 그래픽 절제
- **의미 없는 큰 숫자 금지**: 뒤에 배경 장식으로 넣는 거대 숫자는 §5 content-slop에 해당한다.
- **blob·orb·뭉근한 발광체 금지**: §5 visual-slop 참고.
- **히어로 안에 여러 개의 장식 요소 금지**: 히어로는 한 가지 시각적 메시지에 집중한다.

### 대비와 여백
- 텍스트와 배경 대비는 WCAG AA 이상.
- 히어로 콘텐츠 주변에 충분한 여백을 확보한다. 꽉 찬 히어로는 숨막히게 느껴진다.
- CTA 버튼은 배경과 강한 대비를 가진다 — 색은 DESIGN.md 토큰에서.

## 7. 팔레트 · 머티리얼 · 그라데이션 규율

### 팔레트 일관성
- **DESIGN.md 토큰 팔레트를 페이지 전체에 일관 적용한다.** 구간마다 테마를 바꾸지 않는다.
- 한 페이지가 하나의 브랜드 세계처럼 느껴져야 한다.
- 구간 배경색은 DESIGN.md 팔레트 내의 명도 변주만 허용한다.

### 허용하는 그라데이션
아래 3가지는 DESIGN.md 팔레트 내에서 허용한다:
- **저채도 팔레트-매치 톤**: 같은 계열 색의 밝기 차이로 만든 부드러운 그라데이션
- **히어로 뒤 단일색 분위기**: 단색 배경의 상단·하단에 아주 미세한 그라데이션 필터
- **소프트 비네트**: 사진 가장자리를 배경색으로 살짝 감추는 비네트 효과

### 금지하는 그라데이션
- **레인보우 메시 그라데이션**: 여러 색이 혼합된 메시 형태
- **purple → blue 전환**: 전형적인 AI/테크 스타트업 그라데이션 — DESIGN.md 팔레트에 해당 색이 있어도 이 패턴은 금지
- **neon glow**: 네온 빛이 번지는 효과
- **그라데이션 텍스트**: H1·서브헤드·CTA 텍스트 자체에 그라데이션 채색

## 8. 포맷 · 발산 · 길이

### 포맷
- **세로 ≤3:1(예: 1:3, `1280x3840`)** — 풀페이지 목업에 맞는 포맷이다.
  - 정확한 픽셀 크기(`--size`)는 SKILL.md의 이미지 생성 절 및 image-gen 제약을 따른다(변 16의 배수, 최대 3840, 비율 ≤3:1).

### 한 페이지 = 한 컴프
- **한 타깃 페이지는 한 1:3 컴프**가 기본이다. 섹션을 따로 N장 내지 않는다.
- 하나의 컴프 안에 게이트1에서 고른 섹션이 모두 담겨야 한다.

### 발산
- **발산 라운드는 `--quality low`로 3~4 방향**을 개별 컴프로 만든다.
- **확정본만 `--quality high`**로 한 번 더 뜬다 — 잔글씨 품질을 끌어올리기 위함.

### 긴 페이지 처리
- 히어로+5섹션 초과 분량은 1:3으로도 넘친다. 이 경우 **상단 핵심 섹션으로 캡**하고, 하단 존이 꼭 필요하면 **독립 1:3 존 컴프**로 따로 만든다.
- **연속 슬라이스 체이닝(긴 페이지를 이어붙인 이미지로 만드는 것)은 금지**한다.
- 풀길이 정밀본은 HTML(`design-html-prototype`)이 만든다 — 이미지로 8섹션을 완전 재현하려 하지 않는다.
