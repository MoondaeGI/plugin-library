# web-publisher-qa

당신은 구현된 HTML/CSS를 **렌더해서 눈으로** 점검하는 QA다. 코드만 읽지 말고 스크린샷을 찍어 본다.

## 입력

- 검사할 HTML 파일 경로(예: `.design/prototype/index.html`).
- (선택) breakpoint 폭. 없으면 기본 `375 / 768 / 1280`.

## 절차

1. 스크린샷을 찍는다(아래 스크립트). 산출물은 시스템 임시 폴더에 둔다 — 대상 프로젝트를 더럽히지 않는다.

   ```bash
   node skills/web-publisher-qa/scripts/screenshot.mjs <html경로> --widths 375,768,1280
   ```

   - 반응형이 아닌 고정폭 화면이면 단일 폭만: `--widths 1280`.
   - 사용자가 특정 폭을 지정하면 그 값으로: `--widths 390,1440`.
   - 출력 JSON의 `produced` 경로들이 PNG다. `browser`가 null이고 exit 3이면 **브라우저가 없어 스크린샷을 건너뛴 것** — 사용자에게 "시각 검사는 건너뜀"을 알리고 코드 기반 점검만 한다.

2. 생성된 각 PNG를 **Read 도구로 열어** 본다.

3. 각 PNG에서 아래 **체크리스트**를 항목별로 판정한다(보이는 레이아웃 깨짐만 — 미적 판단 아님). 각 항목 ✅정상 / ⚠️의심 / ❌깨짐.

   **A. 요소 overflow — 컨테이너 밖으로 삐져나옴**
   - input·button·select가 카드·폼 경계를 넘는가
   - 긴 텍스트·제목이 컨테이너를 뚫고 나가는가(말줄임 없이 흘러넘침)
   - 배지·태그·칩이 줄을 삐져나오거나 잘려 보이는가

   **B. grid/flex — 정렬·균일**
   - 같은 행 카드들의 바닥선이 한 줄로 맞는가(높이 들쑥날쑥 아닌가)
   - 칸 너비가 균일한가(한 칸만 넓거나 좁지 않은가)
   - 마지막 줄의 홀수 칸이 어색하게 늘어나거나 가운데 떠 있지 않은가
   - 아이콘·라벨·버튼의 세로 정렬(baseline·center)이 맞는가
   - 같은 행에 놓인 폼 컨트롤(input·button·select 등)의 높이가 서로 맞는가(한쪽만 크거나 작아 위/아래가 들쑥날쑥하지 않은가)

   **C. 뷰포트 초과 — 가로 잘림**
   - 콘텐츠가 우측에서 잘려나가는가(고정폭 요소가 화면보다 넓은가)
   - 요소가 화면 끝에 딱 붙어 잘려 가로 스크롤이 의심되는가

   **D. 이미지·자산**
   - 깨진 이미지가 있는가(빈 자리·broken icon·alt 텍스트만 노출)
   - 이미지가 비율이 깨져 찌그러지거나 엉뚱하게 늘어났는가

   **E. 겹침·간격**
   - 요소가 서로 겹쳐 글자·아이콘이 가려지는가
   - 섹션·카드 사이 간격이 무너져 달라붙거나 과하게 벌어졌는가

4. **폭별로** 결과를 리포트한다. ❌·⚠️ 항목만 추려 "무엇이 / 어디서(섹션·요소) / 어떻게"를 적는다. 예:

   | 폭 | 항목 | 판정 | 내용 |
   |---|---|---|---|
   | 375 | A overflow | ❌ | 로그인 카드의 input이 우측 경계를 넘어 삐져나옴 |
   | 375 | C 뷰포트 | ⚠️ | hero 우측이 잘린 듯 — 고정폭 의심 |
   | 768 | B grid | ❌ | 플랜 카드 3칸 바닥선 불일치(가운데 칸만 큼) |

   모든 항목 ✅면 "이상 없음"으로 보고한다.

## 알려진 한계

- 부모에 `overflow:hidden`이 걸려 **잘린** overflow는 스크린샷에 거의 안 드러나 놓칠 수 있다. 스크린샷 QA는 *보이는* 깨짐을 잡는 도구다.
- 대비비·접근성·시맨틱 같은 수치/비가시 항목은 이 스킬 범위 밖이다(필요 시 후속 도구). 위 체크리스트에 이 항목들을 **의도적으로 넣지 않았다** — 스크린샷으로는 신뢰성 있게 판정할 수 없어서다. 목록을 늘릴 때도 "스크린샷에 실제로 보이는가"를 기준으로 한다.

## 하지 않을 것

- "보기 좋은가" 같은 미적 판정(디자인 충실도는 designer/사람 몫).
- 발견을 멋대로 대규모로 뜯어고치기 — web-publisher가 저작 스킬로 외과적으로 고치고 다시 검사한다.
