# ppt-plan 이미지 데이터 소스 확장 — 설계

- 날짜: 2026-06-15
- 대상: `skills/ppt-plan/SKILL.md` (단일 파일 변경)
- 선행: `idea` 스킬에서 `devils-advocate` 2라운드 압박 검증 후 `brainstorming` 핸드오프

## 배경·문제

ppt-plan은 "자료 → 전략 → 페이지 설계" 3게이트의 저마찰 발표 기획 인터뷰
스킬이다. 현행 게이트 1(자료)은 텍스트 자료를 "읽고 소화 → 핵심 주장·숫자·구조를
요약해 보여주고 확인받는다"까지 한다. 그러나 현실의 발표 자료는 상당 부분이
차트·표·스크린샷 **이미지**인데, 현행 흐름은 이미지를 데이터 소스로 읽는다는
보장이 없다.

## 범위 (진짜 델타)

**이미지(차트·표·스크린샷)를 디자인 참고가 아니라 데이터/근거 소스로 읽어, 그
안의 수치·사실을 추출해 발표 기획 근거로 쓴다.** 이 하나뿐이다.

- "프롬프트로 입력된 목적·자료 확인 후 인터뷰"는 현행 스킬에 이미 존재 → 새로
  만들지 않는다(재서술 금지).
- 새 게이트·새 산출물·subagent·신뢰도 점수는 만들지 않는다.

## 확정된 결정

1. **추출 수치는 전부(always) 사람 확인을 거친다.** 신뢰도 기반 선별이 아니라
   모든 추출 수치를 확인받는다 — 모델이 자기 신뢰도를 못 믿는 문제를 원천 회피.
2. **subagent 리뷰어는 채택하지 않는다.** 모델끼리 합의는 검증이 아니라 투표라
   상관된 환각에 거짓 초록불을 켤 수 있고, Codex 비전·디스패치 이중 미지수에
   걸리며, 저마찰성과 충돌한다. always 확인을 택한 이상 중복이기도 하다.
3. **최종 권위는 항상 사용자.** 추출 수치 대조의 ground truth는 사람이다.

## 설계 (SKILL.md 변경 4곳)

### 1. 게이트 1 본문 — `자료가 있다` 가지에 하위 항목 추가

```
- **자료가 있다** → 받아서 읽고 소화. 핵심 주장·숫자·구조를 요약해 보여주고 확인받는다.
  - **이미지(차트·표·스크린샷 캡처)가 섞여 있으면** 디자인 참고가 아니라
    *데이터 소스*로 읽어 그 안의 수치·사실을 끌어낸다.
  - 이미지에서 뽑은 **모든 수치는 outline에 넣기 전 always 확인**받는다. 산문
    요약에 섞지 말고 `원본 → 읽은 값` 목록으로 따로 제시한다:
        [매출차트.png] 2024 Q3 매출 → 12.4억 · Q4 → 15.1억  (단위·기간 원본대로)
        이 값들이 원본과 맞나요?
    OCR은 자릿수·축 보간에서 틀리기 쉬우니 **사용자 대조가 최종 권위**다.
  - **이미지를 볼 수 없는 환경(비전 미지원)이면** 추출을 시도하지 말고 "이
    이미지의 핵심 수치를 텍스트로 알려주세요"로 요청한다 — 한쪽에서만 도는
    안전장치를 만들지 않는다.
```

### 2. outline.md 형식 — 출처·메타 표기 한 줄 추가

이미지에서 끌어온 근거는 `근거: <이미지파일>에서 추출 (단위·기간·출처)`로 출처와
메타를 남긴다. 차트 `data` 배열 구조화·검증은 ppt-create(`validate-spec.mjs`)
몫 — plan은 출처 표시까지만 한다.

### 3. description frontmatter — 한 문장 추가

기존 description 끝에: "자료에 차트·표·스크린샷 같은 이미지가 섞여 있어도 데이터
소스로 읽어 수치·사실을 끌어낸다."

### 4. 저마찰성 보존

이미지 처리는 "이미지가 있을 때만" 분기한다. 텍스트만 있는 자료, 전략 상담만
원하는 경로는 현행과 동일하게 가볍게 흐른다.

## 미해소 우려 → 해소 매핑

| 우려 (핸드오프 시점) | 해소 |
|---|---|
| 🔴 Codex 비전 가용성 불확실, 공용 스킬 "한쪽만 도는 안전장치" 금지 | 비전 미지원 시 텍스트 수치 요청으로 graceful 폴백(설계 §1). always 확인 단계가 양쪽 모두 동일하게 동작 |
| 🔴 환각 수치가 검증 게이트 없이 outline→spec 전파 | 추출 수치 always 사용자 대조(결정 1) — 최종 권위는 사람 |
| 🟡 이미지 입력 규약·메타 보존 | 메타(단위·기간·출처)는 outline 근거 줄에 보존(설계 §2). 이미지 임베드(image 레이아웃)는 create 관심사라 범위 밖 |
| 🟡 plan/create 경계 | plan은 출처 표시까지, data 배열화·검증은 create(설계 §2) |
| 🟢 description 트리거·저마찰성 | description에 이미지 언급(§3), 이미지 분기는 조건부(§4) |

## 범위 밖

- 신뢰도 점수, subagent 리뷰어, 별도 게이트·산출물.
- 이미지를 덱에 임베드(image 레이아웃) — ppt-create 몫.
- 차트 `data` 배열 구조화·검증 — ppt-create 몫.

  지시하는가"의 리뷰.
