# Brand Kit HTML — 레이아웃 아키타입 라이브러리

> 2026-06-01 · `design-brand-kit` 스킬의 `overview.html` 저작 다양화

## 문제

`overview.html`이 브랜드가 달라도 거의 같은 모양으로 수렴한다. 원인은 `references/brand-kit-html-direction.md`가 "고정 템플릿 아님 / 변주하라"고 적어두고도 **단 하나의 구체적인 압축 CSS 스켈레톤**(상단 스트립 + 풀폭 히어로 + 6열 룰드 모듈 그리드 + 하단 스트립)을 "검증된 좋은 출발점(단수)"으로 제시하기 때문이다. 완성된 CSS와 섹션→그리드 매핑까지 주어지면 LLM은 거의 항상 그것을 그대로 채택한다 — **유일한 예시 = 사실상의 템플릿**. brand *방향*에는 발산 장치(3열 컨택트 시트)가 있지만 HTML *레이아웃*에는 단 하나의 모범답안만 있다.

## 목표 / 비목표

- **목표**: 브랜드 성격에 따라 HTML 골격이 또렷이 갈리고(주축), 같은 브랜드 안에서도 약간의 변주가 생긴다. 품질 바닥은 유지.
- **비목표**: 실행마다 무작위로 달라지는 것(주축 아님). 템플릿+스크립트 주입 엔진. `BRAND_KIT.md` 산문 파싱 레이어.

## 결정

### 1. 단일 스켈레톤 → 4개 아키타입 라이브러리

구조가 또렷이 다른 4개 포스터 골격. 같은 11섹션·데이터·자산·토큰을 다른 뼈대에 얹는다.

| # | 아키타입 | 구조 | 어울리는 브랜드 신호 | 불변(must-hold) |
|---|---|---|---|---|
| A | **룰드 모듈 그리드** | 상단 스트립 + 풀폭 히어로 + 6열 헤어라인 그리드(카드 박스 없음) + 하단 스트립 | 시스템틱·테크·SaaS·정밀 | 헤어라인 그리드, 카드 박스/그림자 남발 금지 |
| B | **에디토리얼 스프레드** | 비대칭 2단 + 큰 세리프 풀쿼트 + 드롭캡 본문 + 넉넉한 여백 | 럭셔리·문학·따뜻함·에디토리얼 | 비대칭 2단 히어로, 세리프(accent) 풀쿼트 주연 |
| C | **사이드바 + 캔버스** | 좌측 어두운 고정 인덱스(워드마크·컬러 레전드·타이포·목차) + 우측 넓은 캔버스 | 프로덕트·도구·대시보드 | 좌측 어두운 사이드바 인덱스 유지 |
| D | **스택 밴드** | 풀폭 수평 밴드 위→아래로 쌓기, 밴드별 배경색 대비, 풀폭 컬러 바 | 대담·마케팅·하이에너지 | 풀폭 밴드 스택, 밴드 간 배경색 대비 |

기존 `overview.html`(Nooknote)이 곧 아키타입 A다. B/C/D 렌더 검증은 `archetypes-preview.html`(미리보기, 비커밋)로 확인했다.

### 2. 구현 방식 = 제약된 스켈레톤 + 자유 존

각 아키타입은 **구조를 잠그고**(검증된 압축 CSS 골격 = 품질 바닥) **변주 지점을 명시**한다. 변주는 LLM이 브랜드별로 결정 → "조금의 자유도". 템플릿+주입 아님(같은 브랜드 항상 동일 = 거부됨), 순수 자유 저작 아님(수렴 위험).

아키타입당 **자유 존**(이 중에서 브랜드별로 결정):
- 라이트/다크 처리
- 히어로 구성(어떤 자산이 주인공·크롭·오버레이)
- 액센트 장식 사용(룰·드롭캡·색 블록)
- 구조 안에서 어떤 모듈을 넓게/강조할지 + 섹션 순서
- 밀도(airy ↔ packed)

아키타입당 **불변**(위 표) = 정체성이 안 무너지는 선.
**공통 불변** = 현 원칙 1~7(포스터 한 장 느낌·밀집하되 숨 쉬게·고정 로고 시리즈·autocrop·실폰트·색은 시스템으로·섹션 인벤토리).

### 3. 선택 메커니즘 (브랜드 기반, 수렴 방지)

1. **"검증된 출발점(단수)" 프레이밍 제거** — 4개를 "동등한 메뉴 + 기본값 없음"으로 제시. 각 아키타입에 `어울리는 브랜드 신호` 태그.
2. **HTML 저작 전 커밋** — `brief.md`의 "레이아웃 메모"가 **고른 아키타입 + 한 줄 근거(브랜드 성격에 묶어서)**를 명시. 블렌딩 허용("C 골격 + B의 세리프 풀쿼트"). 흐름 Step 4(data-only overview 저작)는 이 메모를 따른다.
3. **분위기 열림(3방향)이면 방향마다 다른 아키타입 배정** — 안전한 SaaS형→A, 프리미엄 에디토리얼형→B, 대담한 실험형→D 식. 구조까지 갈라져 "비주얼만 다른 같은 브랜드 세 해석" 문제도 해결.

## 파일 구조 변경

### `references/brand-kit-html-direction.md` (공통 허브로 재작성)
담는 것:
- **아키타입 선택**: 4개 메뉴 요약표(이름·한 줄 성격·어울리는 신호), 선택 규칙(브랜드 신호 매핑, brief 기록, 블렌딩 허용, 기본값 없음), 열림 3방향 매핑.
- **공통 출력·렌더 규칙**: self-contained `overview.html`(CSS 인라인), 형제 `assets/...` 상대경로 `<img>`, 데이터는 `BRAND_KIT.md`/`brand-tokens.json`에서(지어내지 않음), 실폰트 CDN `<link>`, autocrop 전제, 생성 효율(병렬).
- **공통 불변**: 원칙 1~7.
- 개별 골격은 안 담고 `references/archetypes/<name>.md`로 위임(포인터).

### `references/archetypes/<name>.md` ×4 (신규)
파일: `a-ruled-grid.md` · `b-editorial.md` · `c-sidebar.md` · `d-stacked-bands.md`.
각 파일 포맷:
- **성격 / 어울리는 브랜드 신호** (한 줄)
- **구조 설명** (골격이 무엇인지)
- **압축 CSS 스켈레톤** (그대로 쓰거나 변주; 색·폰트·radius는 tokens에서 — 현 html-direction.md의 스켈레톤 스타일)
- **불변 (must-hold)** — 이 아키타입의 정체성
- **자유 존** — 브랜드별로 결정할 변주 지점

> Codex 번들: `references/`는 스킬과 함께 번들된다(`npm run sync`로 `plugins/personal/` 재생성). 하위 폴더 `archetypes/`도 포함.

### `SKILL.md` (보강)

- `overview.html 저작` 절·흐름 Step 1/4에 "아키타입 선택(brief에 기록)" 언급 추가.
