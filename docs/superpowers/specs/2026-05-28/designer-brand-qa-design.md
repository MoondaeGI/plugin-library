# 설계 문서: designer 에이전트 & design-brand-kit 스킬 책임 분리

**날짜:** 2026-05-28  
**대상 파일:** `agents/designer.md`, `skills/design-brand-kit/SKILL.md`

---

## 배경 및 문제

기존 `design-brand-kit` 스킬의 `입력` 섹션은 "부족하면 합리적 기본값으로 채우되 추측한 항목은 명시한다"는 방식이었다. 결과적으로 에이전트나 스킬 어느 쪽도 사용자에게 체계적으로 질문하지 않고 AI가 추측해서 브랜드 킷을 만들었다.

브랜드 킷은 이후 페이지 이미지·HTML 프로토타입 전체의 기반이므로, 여기서 충분한 정보를 수집하지 않으면 이후 모든 산출물의 품질이 저하된다.

## 결정 사항

**Q&A는 `design-brand-kit` 스킬 안에 둔다.**

`designer` 에이전트는 브랜드 킷 외에도 로고 수정, 페이지 이미지, HTML 프로토타입 등 어느 단계에서든 진입점이 된다. Q&A를 에이전트 레벨에 두면 이미 브랜드 킷이 있는 상태에서 다른 단계를 요청할 때도 Q&A가 실행된다. 따라서 "브랜드 킷 만들기"의 입력 수집은 그 스킬이 직접 책임지는 것이 올바른 경계다.

## 변경 1: `design-brand-kit` 스킬

### 1-1. Q&A 섹션 추가

스킬이 실행되기 전, 입력 수집을 위해 아래 질문 뱅크를 **한 번에 하나씩** 진행한다.

#### 질문 뱅크 (우선순위 순)

| 우선순위 | 질문 | 스킵 조건 |
|---|---|---|
| 1 | 제품명과 한 줄 소개 | 이미 명시된 경우 |
| 2 | 주 타깃 사용자 — 누가, 어떤 상황에서 쓰나요? | 명시된 경우 |
| 3 | 핵심 문제와 가치 제안 | 명시된 경우 |
| 4 | "이 브랜드를 한 사람으로 표현하면 어떤 사람이에요? 직업·말투·옷차림으로 설명해주세요." | 거의 항상 질문 |
| 5 | "이 제품을 쓰고 나서 사용자가 어떤 기분을 느꼈으면 해요?" | 거의 항상 질문 |
| 6 | "절대 이런 느낌은 아니에요 — 가장 피하고 싶은 분위기나 브랜드가 있나요?" | 거의 항상 질문 |
| 7 | "좋아하는 브랜드나 디자인 3개를 꼽는다면? 업계 무관, 이유도 짧게." | 레퍼런스 있으면 스킵 |
| 8 | 기존 색상·로고 여부, 유지할 부분 | 명시된 경우 |
| 9 | 사용 맥락 (웹앱·모바일·마케팅 등) + B2B/B2C | 명시된 경우 |

4~6번이 핵심 — 실제 브랜딩 미팅에서 디자이너가 가장 먼저 꺼내는 질문들이다.

#### Q&A 로직

- **맥락 추론:** 사용자의 첫 메시지에서 이미 알 수 있는 항목은 스킵한다.
- **한 번에 하나:** 한 메시지에 하나의 질문만 한다.
- **모호한 답변은 파고든다:** "분위기 있게요" 같은 추상적 답변은 구체화될 때까지 후속 질문을 이어간다. 횟수 제한 없음.
  - 기준: 이 답변으로 HEX 값이나 타이포 방향을 결정할 수 있는가?
  - 예: "신뢰감" → "전문성·권위 쪽인가요, 따뜻하고 친근한 신뢰인가요?"
  - 예: "미니멀" → "여백·타이포 중심인가요, 아이콘·일러스트는 아예 없애는 건가요?"
- **위임 처리:** 사용자가 "모르겠어요" / "AI한테 맡길게요"라고 명시적으로 위임한 항목만 '미확인'으로 처리하고 브리프 상단에 명시한다.
- **종료:** 큐가 비면 Q&A를 끝내고 파일 생성 단계로 진행한다.

### 1-2. `입력` 섹션 교체

기존의 "부족하면 합리적 기본값으로 채우되" 문구를 제거하고, 위 Q&A로 수집하는 항목 목록과 "추측으로 채우지 않는다"는 계약으로 교체한다.
