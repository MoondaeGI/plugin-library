# brand-kit 메인 보드 "3 시안 발산 → 수렴" 설계

날짜: 2026-05-28

## 배경 / 문제

`design-brand-kit`은 종합 브랜드 오버뷰 보드를 **한 장 만들어 보여주고 피드백 받아 고치는** 1개씩 협업 루프를 따른다. 그런데 브랜드 킷은 이후 모든 디자인 작업의 큰 줄기를 정하는 단계라, 첫 방향을 **눈으로 비교해 고르고 싶다**는 요구가 있다.

이미 `SKILL.md:217`에 "최소 3가지 시각 루트(①안전한 SaaS형 ②프리미엄 에디토리얼형 ③대담한 실험형)를 제안하고 그중 하나를 고른다"는 개념이 있으나, 지금은 **글로만** 제안하고 하나만 렌더한다. 이 3루트를 실제 이미지 시안으로 뽑아 시각적으로 고르게 한다.

핵심 통찰: **진짜 다른 시안은 프롬프트가 달라서 나온다.** `--n`(같은 프롬프트 샘플링)은 "똑같은 걸 몇 장 뽑아 깨끗한 걸 고르기"용이라 시안 용도로는 거의 맞지 않는다. 따라서 "3 시안" 로직은 어느 파이프라인 단계인지 아는 **도메인 스킬(brand-kit)** 이 소유하고, `image-gen`은 순수 메커니즘으로 유지한다.

## 범위

- **포함**: `design-brand-kit`의 **메인 오버뷰 보드 첫 생성 단계**에 "발산 → (재시도) → 수렴" 흐름 추가.
- **제외**:
  - `image-gen.mjs` 변경 없음 (3 시안 = 개별 호출 3번, `--n` 아님).
  - 로고·추가 탐색 이미지는 지금처럼 1개씩.
  - page-image 등 이후 단계는 이번 작업 대상 아님 — 우리가 합의한 틀(로직이 도메인 스킬에 있음) 덕분에 나중에 **page-image의 SKILL.md에 같은 패턴을 더하기만** 하면 되는 순수 가산적 확장이다.

## 흐름

현재 흐름(`SKILL.md:251-257`)의 3단계 "종합 보드" 항목을 다음으로 대체한다.

### 3a · 발산 (divergence)

- 12섹션 보드 구조는 그대로 두고, 3 시각 루트(①안전한 SaaS형 ②프리미엄 에디토리얼형 ③대담한 실험형)를 **각각 다른 프롬프트**로 구성.
  - 기본은 위 3 표준 루트. 단, 디스커버리 Q&A에서 명시적으로 거부된 루트(예: "절대 이런 느낌 아니에요")가 있으면 그 루트만 다른 방향으로 대체한다.
- 각 루트를 `--quality low` 초안으로 **개별 호출** 3번 생성.
  - 파일명: `brand-overview-route-a.png`, `-route-b.png`, `-route-c.png` (`.design/generated/brand-kit/`).
- 3장을 나란히 보여주고 **방향을 고르게** 한다.

### 재시도 (re-roll) 루프 — 3장 다 별로일 때

사용자가 전부 거부하면 두 가지 모드 제공 (런타임에 사용자가 선택):

- **(a) 그대로 다시 뽑기 (순수 가챠)**: 같은 3 루트 프롬프트를 그대로 재호출, 파일명 버전업(`-route-a-v2.png` 등). 같은 방향의 새 무작위 뽑기.
  - 한계 고지: 같은 프롬프트라 같은 루트 안에서 **비슷한 결**이 나온다. 구도·무드 자체가 별로면 (b)를 권한다.
- **(b) 방향 조정**: 사용자에게 "뭐가 별로였는지" 받아 루트를 교체하거나 팔레트·구도 에너지 축을 틀어 **다른 3장**을 생성.

→ 하나라도 마음에 드는 방향이 나올 때까지 반복. 모든 재시도는 `--quality low`(초안 비용 낮음).

### 3b · 수렴 (convergence)

- 고른 루트를 `--quality high`로 재렌더 → `brand-overview.png`.
- 이후 **기존의 한-개씩 피드백 루프**로 진입 (한 번에 한 섹션/한 가지만 고쳐 재생성, lock까지 반복).
- 로고·추가 탐색 이미지는 변경 없이 1개씩.

### 정리 (cleanup)

- 방향이 lock되면 **안 고른 루트·이전 버전 초안 파일을 삭제**하고, 고른 것의 high-quality 보드만 남긴다.

## 비용

- 초안 3장(`low`) → (재시도 시 +3장씩) → 확정 1장(`high`).
- 기존 draft-low/final-high 가이드와 그대로 맞물린다.

## 손볼 파일 (모두 brand-kit 내부)

1. **`skills/design-brand-kit/SKILL.md`**
   - 흐름 섹션(`251-257`)에 3a 발산 / 재시도 루프 / 3b 수렴을 추가.
   - `line 257`("전체를 한꺼번에 생성하지 않는다")에 **발산 단계 1회 예외**(초안 한정, 3 루트) 명시.
   - `line 231`("여러 장은 `--n`이 아니라 개별 호출")은 그대로 유효 — 3장도 개별 호출이므로 강화만.
   - 출력 파일 섹션에 route 초안 파일명 규칙·정리 규칙 추가.
2. **`skills/design-brand-kit/references/brand-kit-image.md`**
   - 3 루트를 어떻게 **다르게 프롬프트화**할지 가이드 추가 (팔레트·타이포·구도 에너지 축으로 분기).
3. **`brand-briefs.md` 구조** (`SKILL.md`의 brand-briefs.md 구조 정의 부분)
   - 보드 브리프가 단일 "이미지 생성 Prompt" 대신 **3 루트 방향**을 담도록 확장.

## 검증

이 변경은 대부분 스킬 마크다운(지시문)이며 `image-gen.mjs` 코드 로직은 바뀌지 않는다. 따라서 검증은:

- `image-gen.mjs --dry-run`으로 3 루트 개별 호출이 의도한 버전 파일 경로(`brand-overview-route-a/b/c.png`, `-v2` 등)를 만드는지 확인.
- 스킬 흐름을 실제로 한 번 태워 발산 3장 → 재시도(a)(b) → 수렴 → 정리가 문서대로 동작하는지 확인.

## 미해결 / 가정

- 재시도 횟수 상한은 두지 않는다 (사용자가 만족할 때까지). 비용은 초안 low라 낮다는 전제.
- 3 루트는 기본 표준이되 (b) 재시도에서 Claude가 유연 조정 — 제품마다 완전 자유 축으로 가지는 않는다(일관성·예측성 유지).
